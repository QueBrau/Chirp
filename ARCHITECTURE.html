Nodes, artifacts and the paths between them

The single fact that most often surprises a new reader: chirp-api and chirp-ws are the same container image with every route mounted on both. They are not an API tier and a socket tier by construction. What separates them is the URL a client is pointed at, and the scaling knobs set on each.

Figure 2 — Domain class diagram

The entities permission actually depends on

Forty-two tables exist; these are the ones that carry authorization or money. The rule the whole model encodes: Membership is the fact, User.account_type is only a claim. A user can set the latter at signup and it must never gate anything.

Read account_type as a warning label

It is drawn in the risk colour on purpose. It is set by the user at signup, is presentation-only, and was — until 30 August — the gate on who could post to the alumni job board. Any authorization that starts from this attribute is a bug by construction. Use Membership.role, User.campus_verified_at, or User.is_platform_admin.

The ciphertext column is not yet ciphertext

The server is built correctly for end-to-end encryption: it stores the payload as opaque bytes, never parses it, and the prekey tables exist (signed_prekeys, one_time_prekeys, kyber_prekeys). The client half does not exist — src/crypto/signal.ts is a typed stub whose every function throws, with zero callers. The composer is disabled, so nothing can be sent today, but the Messages screen still reads "End-to-end encrypted". Fix the copy before the composer is ever enabled. Tracked as c254.
